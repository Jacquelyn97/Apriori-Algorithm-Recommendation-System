# Notebook 答辩展示顺序（不改原内容版）

## 一、推荐展示总顺序（按论文逻辑）

1. `chap3.ipynb`（数据来源统一与商品映射）
2. `chap4.ipynb`（清洗与事务构建）
3. `chap5.ipynb`（Apriori 建模与规则分级）
4. `chap5_3_visualization.ipynb`（可视化与业务解释）

这条顺序对应论文主线：  
**数据准备 -> 数据清洗 -> 模型构建 -> 结果展示**。

## 二、每个 Notebook 的定位区分（你答辩时可直接说）

- `chap3.ipynb`：解决“数据能不能直接用”的问题，完成字段标准化、商品名称映射与兜底策略。
- `chap4.ipynb`：解决“数据干不干净、是否可挖掘”的问题，完成时间窗过滤、状态/支付过滤、缺失检查、事务构建。
- `chap5.ipynb`：解决“模型怎么建、参数怎么定、规则强不强”的问题，完成 Apriori 参数配置、规则输出、L1-L4 分级。
- `chap5_3_visualization.ipynb`：解决“结果怎么落地给业务看”的问题，展示 Gold Match、用户画像、分群与实时销售看板。

## 三、你可按这个讲解节奏（每段 30-60 秒）

1. **数据准备（chap3）**  
   两个数据源（公开数据 + 自有小程序数据）先做字段统一，再做商品名映射，保证不同来源商品可在同一词表上比较。

2. **数据清洗（chap4）**  
   先按 180 天时间窗保留近期数据，再过滤无效订单（状态与支付校验），再做关键字段完整性检查，最后按订单聚合为购物篮事务。

3. **模型构建（chap5）**  
   用 Apriori 挖频繁项集和关联规则，核心阈值为 `MIN_SUPPORT=0.03`、`MIN_CONFIDENCE=0.1`，并用 Lift 过滤无效关联。

4. **结果解释（chap5 + chap5_3_visualization）**  
   将规则按 L1-L4 分级，L1 用于直接套餐推荐，L2-L4 用于个性化推荐和运营探索；可视化页面帮助管理者快速决策。

## 四、答辩时的开场一句话模板

“我的实验链路是先把多源订单数据标准化，再通过五步清洗构建事务数据，接着用 Apriori 做规则挖掘和分级，最后把规则通过接口和可视化页面落地到推荐与运营场景。”
